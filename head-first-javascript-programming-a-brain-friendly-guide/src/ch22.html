NGUYÊN LÝ CỐT LÕI

Giải phẫu cây DOM và quy trình tạo lập

TL;DR: Trình duyệt phân tích cú pháp HTML từ trên xuống dưới để xây dựng một cây đối tượng ngược với gốc là document.

Khi trình duyệt nạp một trang web, nó không chỉ hiển thị văn bản thuần túy mà thực thi một thuật toán phân tích cú pháp (parsing). Khởi đầu bằng một document node tối cao ở đỉnh. Tiếp theo, trình duyệt bóc tách thẻ <html>, gắn nó làm con của document, rồi đệ quy lặp lại cho mọi thẻ con, nhánh và lá bên trong. Kết quả là một tập hợp các đối tượng (element objects) nằm trong bộ nhớ.

THỰC CHIẾN LẬP TRÌNH

Kết nối JavaScript với HTML qua getElementById và innerHTML

TL;DR: Sử dụng getElementById để lấy đối tượng element và innerHTML để thay đổi nội dung động.

HTML và JavaScript vận hành theo hai trường phái khác nhau: HTML mang tính khai báo (declarative), còn JavaScript mang tính mệnh lệnh (imperative). Cầu nối duy nhất giữa chúng tại tầng DOM là phương thức getElementById(). Khi gọi phương thức này trên đối tượng document, trình duyệt trả về một tham chiếu đến element object thực tế. Sau đó, thông qua thuộc tính innerHTML, kỹ sư có thể đọc hoặc ghi đè toàn bộ nội dung HTML bên trong phần tử đó ngay lập tức.

Hố sâu tử thần: Chạy script trước khi DOM hoàn thành

TL;DR: Đặt script trong thẻ head khi DOM chưa hình thành sẽ trả về null và gây lỗi ngầm.

Một lỗi sơ đẳng của lập trình viên sơ cấp là đặt thẻ <script> ở phần <head> và gọi ngay document.getElementById(). Vào thời điểm đó, trình duyệt chưa đọc đến phần <body>, đồng nghĩa với việc các phần tử HTML chưa được chuyển đổi thành node trong DOM. Kết quả là hàm trả về null, gây gãy khúc logic ứng dụng mà không báo lỗi dừng chương trình rõ ràng.

TỔNG KẾT CHƯƠNG

Thực hành & Kiểm tra kiến thức

Chương này bóc tách bản chất của Document Object Model (DOM) - cấu trúc dữ liệu cây ngược (inverted tree) mà trình duyệt xây dựng từ mã nguồn HTML. Trình duyệt bắt đầu từ node `document` cao nhất, duyệt qua từng thẻ HTML lồng nhau để tạo ra tập hợp các đối tượng (element objects) chứa thuộc tính và phương thức. JavaScript không thể trực tiếp thao tác văn bản HTML tĩnh; nó giao tiếp với trang web thông qua "lỗ sâu" (wormhole) là phương thức `document.getElementById()`. Khi lấy được một element object, kỹ sư có thể thay đổi thuộc tính `innerHTML` để cập nhật nội dung trang theo thời gian thực. Một cạm bẫy kinh điển được chỉ ra là thực thi mã JavaScript trong thẻ `` trước khi DOM được tải xong, dẫn đến việc trả về `null` và lỗi ngầm.

Kiểm tra kiến thức cốt lõi

Câu 1: Phương thức getElementById trả về cái gì nếu ID truyền vào không tồn tại trong trang?

  1. Một chuỗi rỗng ('')
  2. Một đối tượng lỗi (Error object)
  3. Giá trị null
  4. Số nguyên 0

Khi không tìm thấy ID khớp trong cây DOM, phương thức getElementById sẽ trả về giá trị null. Do đó, việc kiểm tra null trước khi gọi thuộc tính trên kết quả trả về là một tiêu chuẩn an toàn bắt buộc.

Câu 2: Tại sao việc đặt mã JavaScript ở thẻ gọi getElementById('greenplanet') lại thường thất bại?

  1. Vì JavaScript không hỗ trợ tìm kiếm phần tử trong thẻ head
  2. Vì trình duyệt chưa phân tích cú pháp phần body nên phần tử chưa tồn tại trong DOM
  3. Vì cú pháp getElementById yêu cầu phải có tiền tố window
  4. Vì thẻ script trong head bị cấm thực thi DOM API

Trình duyệt đọc HTML từ trên xuống dưới. Khi script ở head chạy, trình duyệt chưa hề chạm tới body, do đó cây DOM chưa chứa các phần tử nằm ở dưới.

Câu 3: Thuộc tính innerHTML đại diện cho điều gì?

  1. Chỉ định dạng CSS của phần tử
  2. Toàn bộ nội dung và thẻ HTML nằm bên trong phần tử đó
  3. Địa chỉ IP của máy chủ chứa trang web
  4. Tên định danh duy nhất (ID) của thẻ

innerHTML đại diện cho nội dung 'bên trong' (inner) của element, bao gồm cả các thẻ HTML lồng nhau và văn bản thuần túy.
