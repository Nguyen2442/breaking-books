KIẾN TRÚC DỮ LIỆU

Phân định rạch ròi Undefined và Null

TL;DR: Undefined là chưa khởi tạo, Null là cố tình gán không có đối tượng.

Trong kiến trúc phần mềm, việc phân biệt undefined và null giúp tối ưu hóa việc quản lý trạng thái bộ nhớ. Undefined xuất hiện tự nhiên khi biến chưa được cấp giá trị hoặc thuộc tính không tồn tại. Ngược lại, null là giá trị chủ động được gán bởi lập trình viên để biểu thị sự vắng mặt có chủ ý của một đối tượng.

TỔNG KẾT CHƯƠNG

Thực hành & Kiểm tra kiến thức

JavaScript sở hữu một hệ thống kiểu dữ liệu linh hoạt nhưng đầy rẫy cạm bẫy lịch sử. Để vận hành các hệ thống lớn an toàn, kỹ sư buộc phải nắm vững bản chất của kiểu nguyên thủy (Primitive) và kiểu tham chiếu (Object). Chương này mổ xẻ 3 giá trị dị biệt: undefined (biến chưa khởi tạo), null (đại diện cho đối tượng trống/không tồn tại, trả về type 'object' do lỗi lịch sử), và NaN (Not-a-Number nhưng lại mang kiểu 'number', duy nhất trong JS không bằng chính nó). Việc kiểm tra lỗi type đòi hỏi các hàm chuyên dụng như isNaN() thay vì toán tử so sánh thông thường. Hiểu sâu các cơ chế này giúp loại bỏ hoàn toàn các lỗi runtime khó đỡ trong các ứng dụng web quy mô lớn.

Câu 1: Kết quả của phép so sánh NaN === NaN là gì?

  1. true
  2. false
  3. undefined
  4. TypeError

NaN là giá trị duy nhất trong JavaScript không bằng chính nó theo chuẩn IEEE floating point, do đó NaN === NaN luôn trả về false.
