KIẾN TRÚC VẬN HÀNH

Cơ chế ép kiểu ngầm trong toán tử so sánh lỏng

TL;DR: JavaScript tự động chuyển đổi kiểu dữ liệu của toán hạng khi sử dụng toán tử ==.

Khi thực hiện so sánh bằng toán tử ép kiểu ngầm (type coercion), JavaScript không ném lỗi khi hai vế lệch kiểu. Thay vào đó, nó áp dụng các quy tắc tiêu chuẩn: chuyển chuỗi thành số, chuyển boolean thành 1 hoặc 0, và đánh giá null bằng undefined.

Tình huống thực tế

Hệ thống thương mại điện tử Tiki khi lọc sản phẩm theo khoảng giá từ URL query parameters (vốn là chuỗi '100000') nếu dùng toán tử == sẽ vô tình khớp đúng với số 100000, nhưng sẽ gặp rủi ro logic lớn nếu tham số truyền vào là rỗng hoặc chuỗi rác.

TỔNG KẾT CHƯƠNG

Thực hành & Kiểm tra kiến thức

Trong JavaScript, hệ thống kiểu dữ liệu yếu (weak typing) mang lại sự linh hoạt nhưng ẩn chứa rủi ro lớn khi sử dụng toán tử so sánh lỏng lẻo (==) và toán tử số học/chuỗi (+). Khi so sánh hai giá trị khác kiểu (như số và chuỗi, hoặc boolean với số), JavaScript tự động thực hiện ép kiểu ngầm (type coercion) dựa trên các quy tắc xác định trước: chuỗi được cố gắng đổi thành số, boolean đổi thành 1 hoặc 0, và null/undefined được coi là tương đương. Tuy nhiên, cơ chế này dễ dẫn đến các kết quả phản trực giác (như '1' == true hay 1 == ''). Ngược lại, toán tử nghiêm ngặt (===) không thực hiện bất kỳ phép chuyển đổi nào: nếu khác kiểu hoặc khác giá trị, kết quả lập tức là false. Kiến trúc sư và kỹ sư phần mềm cao cấp phải nắm vững các quy tắc này để lựa chọn tiêu chuẩn code sạch, ưu tiên sử dụng === nhằm đảm bảo tính dự đoán (predictability) của hệ thống.

Kiểm tra kiến thức cốt lõi

Câu 1: Biểu thức nào sau đây trả về kết quả là true?

  1. '0' === 0
  2. null == undefined
  3. 1 == true
  4. Cả 2 và 3 đều đúng

null == undefined luôn trả về true theo quy tắc Case #3. 1 == true trả về true vì boolean true được ép thành số 1. Riêng '0' === 0 trả về false vì khác kiểu dữ liệu.
