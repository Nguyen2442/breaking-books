NGUYÊN LÝ CỐT LÕI

Tương tác với Trang Web và Công cụ Debug

TL;DR: Sử dụng DOM để điều khiển trang và console.log để debug hiệu quả.

Tương tác trực tiếp với Document Object Model (DOM) cho phép mã JavaScript thay đổi cấu trúc, nội dung và phong cách của trang web động. Trong khi các phương thức cũ như document.write hay alert gây cản trở trải nghiệm người dùng, console.log là tiêu chuẩn vàng để kiểm tra trạng thái biến và gỡ lỗi trong môi trường phát triển.

KIẾN TRÚC HIỆU NĂNG

Tối ưu hóa thứ tự tải nguyên nhân Render-Blocking

TL;DR: Đặt thẻ script ở cuối body giúp tối ưu hóa thời gian hiển thị trang web.

Trình duyệt thực thi mã JavaScript ngay khi nó được tải về. Nếu đặt thẻ <script> ở phần <head>, quá trình dựng trang sẽ bị đình trệ. Giải pháp kiến trúc chuẩn là liên kết tệp JavaScript bên ngoài và đặt ở cuối thẻ <body> để đảm bảo giao diện hiển thị trước khi xử lý logic.

Tình huống thực tế

Các trang báo điện tử lớn như VnExpress hay 24h đặt tất cả script ở cuối trang hoặc dùng async/defer để đảm bảo bài viết tải xong ngay lập tức trên mạng di động 4G yếu.

Thực hành & Kiểm tra kiến thức

Chương này mổ xẻ cách trình duyệt tiếp nhận, phân tích và thực thi mã JavaScript, từ việc tương tác với Document Object Model (DOM) cho đến tối ưu hóa thứ tự tải script trong trang web. Kiến trúc sư phần mềm cần nắm vững vị trí đặt thẻ ?

  1. Cả hai đoạn mã đều chạy bình thường
  2. Mã bên trong thẻ sẽ bị bỏ qua hoàn toàn
  3. Trình duyệt sẽ báo lỗi cú pháp Fatal Error
  4. Chỉ có mã bên trong chạy, file src bị bỏ qua

Theo chuẩn HTML, khi một thẻ script có thuộc tính src, trình duyệt chỉ tải file được chỉ định và bỏ qua hoàn toàn nội dung viết bên trong cặp thẻ đó.
