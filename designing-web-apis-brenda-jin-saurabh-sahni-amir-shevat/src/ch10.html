Xác định điểm nghẽn và mở rộng thông lượng API

Tóm tắt cốt lõi

Phát hiện chính xác điểm nghẽn phần cứng và tối ưu hóa thông qua caching, database index và xử lý bất đồng bộ.

Trước khi thực hiện bất kỳ tối ưu hóa nào, kỹ sư cần phải định vị chính xác điểm nghẽn của hệ thống thông qua instrumentation và performance profiling. Các điểm nghẽn trong hệ thống phân tán thường xuất hiện ở bốn tầng tài nguyên phần cứng chính.

Các trường hợp phân loại điểm nghẽn phổ biến:

  • Disk I/O: Gây ra bởi các câu lệnh truy vấn database đắt đỏ, thiếu index hoặc truy cập ổ cứng cục bộ quá nhiều lần.
  • Network I/O: Xảy ra khi ứng dụng phụ thuộc vào các dịch vụ bên ngoài gọi qua nhiều trung tâm dữ liệu khác nhau.
  • CPU Bottleneck: Do mã nguồn kém tối ưu, thực thi các thuật toán phức tạp hoặc vòng lặp chứa câu lệnh query bên trong.
  • Memory Bottleneck: Hệ thống thiếu RAM dẫn đến việc swap liên tục hoặc bị hệ điều hành tiêu diệt tiến trình (OOMKilled).

Sau khi xác định điểm nghẽn, các giải pháp như horizontal scaling, database indexing, application caching và asynchronous task queues (như Celery) sẽ được kích hoạt để tăng tốc độ phản hồi và giảm độ trễ P99.

Thực chiến tại hệ thống thanh toán MoMo/ZaloPay

Trong các giờ cao điểm xử lý hàng triệu giao dịch đối soát, các kỹ sư tại MoMo phải sử dụng profiler để tách biệt các tác vụ ghi log và gọi bên thứ ba ra các hàng đợi bất đồng bộ (asynchronous task queues), đồng thời tạo index chuyên biệt trên bảng giao dịch để tránh nghẽn Disk I/O.

Thực hành & Trắc nghiệm Active Recall

Chương này mổ xẻ toàn diện các kỹ thuật cốt lõi để scale hệ thống API từ quy mô nhỏ đến các đợt bùng nổ tải trọng lớn hàng triệu request. Bắt đầu từ việc xác định chính xác các điểm nghẽn (Bottlenecks) tại Disk I/O, Network I/O, CPU và Memory thông qua công cụ profiler và load testing. Tiếp theo, sách phân tích các chiến lược mở rộng thông lượng thông qua việc tối ưu cơ sở dữ liệu (Database Indexing), Caching tại tầng ứng dụng và edge, cùng việc xử lý các tác vụ nặng theo hướng bất đồng bộ (Asynchronous Processing). Đồng thời, việc tiến hóa thiết kế API thông qua WebHooks, WebSockets, GraphQL, và các endpoint dạng bulk giúp cắt giảm đáng kể số lượng HTTP round-trip không cần thiết. Cuối cùng, các cơ chế phân trang nâng cao (Cursor-based Pagination) và hệ thống kiểm soát tốc độ truy cập (Rate-Limiting) được áp dụng để bảo vệ tuyệt đối hạ tầng trước các cuộc tấn công DDoS hoặc hiện tượng bão kết nối từ client.

Câu 1: Kỹ thuật phân trang nào sau đây KHÔNG PHÙ HỢP cho các tập dữ liệu lớn và thay đổi liên tục?

  1. Cursor-based pagination sử dụng unique ID
  2. Cursor-based pagination sử dụng Unix timestamp
  3. Offset-based pagination sử dụng tham số limit và offset
  4. Phân trang dựa trên opaque strings

Offset-based pagination rất kém hiệu quả khi offset lớn vì database phải quét và bỏ qua toàn bộ các hàng trước đó, đồng thời dễ dẫn đến việc lặp hoặc sót dữ liệu khi có bản ghi mới được thêm/xóa trong lúc client đang phân trang.
